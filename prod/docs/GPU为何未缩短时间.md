# GPU 为何没有缩短时间

给客户说明用。只写在 S810 全量上比过的结果。没有全量对比的节点，不写成「GPU 更慢」。

验证机是 2 张 Tesla T4。空三匹配用 32 个 CPU 进程。正射这次开到 48 个进程。界面上的「任务 GPU」只表示提交时选了哪张卡，不表示该步真的在用显卡计算。

正式任务里，测过、确认开 GPU 更慢、因此改回 CPU 的，只有下面两处。

## 1. 空三 · 像对匹配

同一批 S810 影像，各跑一次全流程。

| | 用什么 | 匹配耗时 | 整次任务 |
| --- | --- | ---: | ---: |
| 只开 CPU | 32 个核做近似匹配 | 508 秒 | 2.2 小时 |
| 匹配改走 GPU | 1 张 T4 做精确匹配 | 2339 秒 | 2.9 小时 |

GPU 大约慢 4.6 倍。连接点都在 184 万条左右，重投影误差都是 0.57 像素，成果精度没有因为改回 CPU 变差。

CPU 更快的原因：32 个核同时查找够用的相近点。GPU 那条路径要在一张 T4 上做精确查找，查的候选更多。当时显卡利用率大约 60%，卡是忙的，墙钟仍然更长。一张卡比不过 32 个核一起算。

所以匹配固定走 CPU。

## 2. 正射 · 把照片贴到地图上

正射每一块里，大约九成时间是在选拼接线（这块用哪张照片）。拼接线在 CPU 上算，没有 GPU 实现。GPU 能接的只有贴图：按地形把照片采到地图格子上，大约只占每块时间的一成。

32 个进程同时往一张 T4 上贴时，每个进程都要占一块卡上的位置，卡被排队拖住，利用率接近 0，整段正射比纯 CPU 更慢。进程超过 8 个就不再把贴图交给 GPU。这次正射是 48 个进程，贴图留在 CPU 上。

多光谱正射那一行（450nm 到 850nm，约 57 分钟）就是这 7 个波段在 CPU 上一起算的时间，不是显卡在跑。Color 单独约 6 分钟，7 个波段大约是它的 7 倍多，和工作量一致。

另外一次开 GPU 时，曾把多光谱「几何只算一次」关掉，七个波段各算一遍投影，多光谱正射从约 80 分钟回到数小时。这一点已经改掉：即使用 GPU，几何也只算一次。当前正式路径仍不用 GPU 贴图，因为进程一多，卡会排队，墙钟更长。

## 3. 其余节点

下面这些节点没有「开了 GPU 反而更慢」的全量对比。这次任务就是在 CPU 上算的。

| 节点 | 说明 |
| --- | --- |
| 输入输出、影像编目、质量报告 | 读写和出报告，没有对应的 GPU 计算 |
| 空三里的平差、前方交会 | 在 CPU 上解方程，没有 GPU 全量对比 |
| 密集匹配、DSM | 在 CPU 上算；DSM 只有几秒 |
| 正射里的拼接线 | 在 CPU 上算，这是正射的大头 |

## 4. 和 25 分钟目标的关系

S810 最近一次全流程大约 2 小时出头：空三约 46 分钟，密集匹配约 18 分钟，多光谱正射约 57 分钟，Color 正射约 6 分钟，DSM 和质量报告可以忽略。

空三和密集匹配加起来已经约 64 分钟，还没算正射。在这台 T4 验证机上，把上面两处改回 GPU 不会缩短到 25 分钟，实测会更长。25 分钟是客户现场 RTX 4090 上的目标，不能用 T4 的耗时换算。
