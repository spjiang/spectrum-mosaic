# 需求符合性评估与重构方案

> 对照材料：`需求材料/多光谱拼图需求 0908评估.xlsx`（33 条需求）、`需求材料/0611hsl_Report.pdf`（LiMapper 4.0 质量报告，9 页）、`测试正式数据/MAX_20251017/拼图结果`（商业软件成品）  
> 被评估代码：`prod/source/ms_mosaic`（catalog / geo / mosaic / report / pipeline）  
> 结论日期：2026-09-17

---

## 0. 三句话结论

1. **当前代码不满足需求，差距是原理级的，不是参数或 bug。** 它只做了 POS 直接地理定位 + `rasterio.merge`，没有空三（SfM）、没有密集点云、没有 DSM、没有拼接线。重叠处「后一帧盖住前一帧」，所以你看到的错位和重影是必然结果。
2. **不应该自己从零写空三。** 业界开源对标 Pix4D / Metashape 的是 **OpenDroneMap（ODM）**，它原生支持多光谱主波段重建 + 波段配准 + DSM + 正射，且本批数据的 XMP 就是 **Pix4D Camera 命名空间**，ODM 能直接读。
3. **质量报告可以做到与 LiMapper「同结构、同字段、可替代验收」，但数值不可能逐位相同。** 报告里的关键点数、连接点数、重投影误差、相机自标定 K1/K2/K3 等，都是各家空三算法的内部统计量；换引擎必然换数值。要求「一模一样」只能落在版式与字段上。

## 1. 为什么现在的拼接结果「完全不对」

### 1.1 根因链

```text
无空三 → 每帧位置只信 GPS（无 RTK，标称 3 m）
       → 姿态只用 XMP yaw，pitch/roll 未参与，地面按水平面
       → 帧与帧之间没有连接点约束，相邻帧可错开数米
无 DSM → 正射只是"按比例缩放贴图"，地物高度造成的位移没有纠正
无拼接线 → merge 的重叠规则是"后写覆盖先写"，接缝处直接跳变、产生重影
```

### 1.2 与商业软件成品的差距

| 项 | `拼图结果/`（商业软件） | 当前 `ms_mosaic` |
| --- | --- | --- |
| 几何 | 空三 + 密集点云 + DSM 逐像素正射 | POS 直投，地面当平面 |
| 影像对齐 | 1888/1896 注册，重投影误差 0.41 px | 无对齐，帧间无约束 |
| 重叠处理 | 拼接线 + 多级融合 | 后写覆盖，肉眼可见重影 |
| DSM | `DSM.tif`，0.094 m | 无 |
| 波段一致性 | 主波段重建 + 其余刚性配准 | 8 通道各自独立贴图 |
| 成果 | group0（RGBA）+ group1–7 + DSM | rgb.tif + 7 个单波段 |

结论：**当前代码只是「能上地图的预览」，不是正射产品。** 之前文档里把它定位成阶段 1 保底，现在要按需求交付，必须换几何内核。

### 1.3 数据事实核查（已实测确认）

| 事实 | 值 | 对方案的影响 |
| --- | --- | --- |
| 文件总数 | 5363（671 RGB + 668×7 波段 + 2×7 白板） | 3 个曝光缺多光谱，需按 UUID 对齐而非只按编号 |
| 商业成品 | `DSM.tif` + `Orthomosaic_pix_surf_group0`（RGB）+ `group1–7`（7 波段） | 成果契约就是 1 DSM + 8 张正射 |
| XMP 命名空间 | `pix4d.com/camera/1.0` | ODM 可直接识别多光谱分组 |
| `BandName` / `CentralWavelength` | `Green` / `550` 等 | 主波段选 `Green`，对应 REQ-04-01 |
| `PerspectiveDistortion` | `0,0,0,0,0` | **厂家未给畸变系数**，必须靠空三自标定（LiMapper 报告里的 K1/K2/K3 也是自标定出来的） |
| `Irradiance` / `BandSensitivity` / `BlackCurrent` / `ExposureTime` | 均有值 | 可启用 `--radiometric-calibration camera+sun` 出反射率 |
| 白板帧 `_W` | 每波段 2 张 | 可作辐射定标参考，不能进重建 |
| `RtkUsage` / `GPSXYAccuracy` / `GPSZAccuracy` | `0` / `3.0 m` / `5.0 m` | **无 RTK**，绝对精度上限就在米级，直接决定 REQ-05-01 的口径 |

## 3. 质量报告必须做到什么

`0611hsl_Report.pdf` 共 9 页，字段清单如下。这就是报告生成器的**验收规格**。

### 3.1 概述
工程名称、创建时间、影像数目、测区面积、平均航高、地面控制点数、参考坐标系（含 `egm_none`）、影像对齐耗时、生成密集点云耗时、生成 DSM 耗时、生成正射影像耗时、正射与 DSM 缩略图

### 3.2 2D 关键点检测
2D 关键点总数、最大影像尺度、影像关键点数最大值、影像关键点数均值、特征点最多的影像、特征点最少的影像、潜在较差影像列表

### 3.3 2D 关键点匹配
连接点数目、像对筛选模式、单张影像最大两视图连接点数量、单张影像平均连接点数量、连接点最多/最少的影像、关联影像序列（每组影像序号列表）

### 3.4 相机标定信息（每波段一行）
影像组号、相机类型、影像尺寸、焦距（像素）、像主点、K1/K2/K3、P1/P2、B1/B2、注册影像数、影像均方根误差

### 3.5 空中三角测量
已注册影像（如 1888/1896）、主波段、地理参考模式、外点阈值、调整内参列表、调整外参、稀疏 3D 点数量、2D 观测值数量、单张影像平均 2D 观测值、3D 稀疏点最多/最少影像、重投影误差均值、均方根重投影误差、未注册影像索引列表

### 3.6 密集点云 / DSM / 正射影像
密集点数量、质量、类型（2.5D）、平均点间距；DSM 分辨率；正射模式、融合层级、颜色校正、最大倾斜角、分辨率

### 3.7 基于 GPS 配准
GPS 参考点数目、配准 RMSE、RMSE-X/Y/Z、各轴误差最小/最大值明细（含初始与优化 GPS 坐标、dx/dy/dz）、误差范围直方图（分箱百分比）、逐帧配准明细表

### 3.8 视图
相机位置视图（优化 POS vs 初始 POS）、空三视图（可视区域 / 3D 稀疏点 / 相机位置）、重叠度视图（1–≥10 分级）

### 3.9 航线信息
航线序列（组号）→ 影像列表、较差航向重叠率表、较差旁向重叠率表、平均航向重叠率、平均旁向重叠率

### 3.10 关于「一模一样」

可以做到：**同样的页序、章节标题、表格列、单位、PDF 版式**，让对方拿去验收无需适配。

做不到：**数值逐位相同**。LiMapper 的 13858216 个关键点、0.410198 px 重投影误差，来自它自己的 SIFT 参数与平差实现。换任何引擎（含 Metashape、Pix4D、ODM）数值都不同。这是软件差异，不是缺陷。

## 4. 业界方案调研

### 4.1 商业软件用的是什么

| 环节 | 业界算法 | Pix4D / Metashape 对应 |
| --- | --- | --- |
| 特征 | SIFT / AKAZE / SuperPoint | Pix4D 自研 SIFT 变体 |
| 匹配 | 词袋 + 近邻 + RANSAC | Metashape "generic/reference preselection" |
| 空三 | 增量式 SfM + 光束法平差（Ceres） | `Align Photos` / `Initial Processing` |
| 自标定 | Brown-Conrady k1k2k3 p1p2 + b1b2 | 报告里的相机标定表 |
| 密集点云 | SGM / PatchMatch MVS | `Build Dense Cloud` / `Point Cloud Densification` |
| DSM | 点云 TIN / IDW 插值 | `Build DEM` |
| 正射 | DSM 逐像素反投影 | `Build Orthomosaic` |
| 拼接线 | 图割能量最小化（color+gradient+DSM 高程） | Metashape `refineSeamlines` |
| 融合 | 多频段/拉普拉斯金字塔混合 | Pix4D `Minimal/Full/Deghost`、Metashape `Mosaic/Average` |

拼接线的学术基准：Li et al., *Optimal seamline detection for multiple image mosaicking via graph cuts*, ISPRS JPRS 2016；Chen et al., *Automatic Seamline Network Generation with DSM*, RS 2014。核心是把重叠区建成图，用颜色差、梯度、DSM 高程做代价，图割求最优缝，避免缝穿过建筑。

### 4.2 开源可用引擎

| 方案 | 能力 | 多光谱 | 评价 |
| --- | --- | --- | --- |
| **OpenDroneMap (ODM)** | SfM(OpenSfM) + MVS + DSM/DTM + 正射 + 报告 | **原生**：`--primary-band`、自动波段配准、`--radiometric-calibration` | **推荐**。Pix4D/Metashape 的开源对标，一条命令出全套 |
| COLMAP + OpenMVS | SfM + MVS 质量高 | 无 | 需自己写 DSM、正射、多光谱逻辑 |
| MicMac (IGN) | 完整摄影测量 | 弱 | 上手陡峭，文档法语为主 |
| AliceVision | SfM + MVS | 无 | 偏影视三维重建 |

### 4.3 为什么 ODM 特别适合这批数据

1. 本数据 XMP 命名空间是 `http://pix4d.com/camera/1.0`，含 `BandName`、`CentralWavelength`、`RigCameraIndex`、`CaptureUUID` —— ODM 的多光谱识别正是读这些。
2. `--primary-band` 直接对应 **REQ-04-01**「默认绿波段为主波段，仅主波段执行特征匹配与重建」。
3. 自动波段配准（homography）对应「其余波段刚性变换配准至主波段」。
4. `--dsm` 出 DSM，`--pc-quality ultra/high/medium/low` 正好是 **REQ-02-02** 四级档位。
5. `--orthophoto-resolution` 对应 **REQ-03-06**，`--max-concurrency` 对应 REQ-07-03 多核。
6. 输出 `odm_report/`、`cameras.json`、OpenSfM `reconstruction.json` / `tracks.csv`，是生成 LiMapper 式报告的**数据来源**。

## 5. 重构架构

```text
MAX_20251017_001/（只读）
        │
   [1] catalog  认文件、读 POS/波段/UUID、滤白板与大倾角        ← 复用现有 catalog.py
        │
   [2] stage    在工作区建 ODM 项目（符号链接或硬链接，不拷原图）
        │        images/ 全波段同放一处；写 geo.txt / 相机标定
        ▼
   [3] ODM 引擎（Docker）  ← 业界标准，替换当前 POS 直投
        │   OpenSfM 空三（主波段 550nm）→ 波段配准 → 密集点云
        │   → DSM → 正射（拼接线 + 多频段融合，多光谱禁用色彩校正）
        ▼
   [4] postprocess  拆分 N 波段正射为单波段 GeoTIFF、伪彩色合成、KML、压缩策略
        │
   [5] report   读 ODM/OpenSfM 统计 → 生成 LiMapper 同构 PDF + JSON + 明码日志
        │
        ▼
out/
  dsm/        dsm.tif、dtm.tif、dsm.kml
  mosaics/    group0_rgb.tif、group1_450nm.tif … group7_850nm.tif、pseudocolor.tif、*.kml
  process/    分步骤 PNG 过程图 + 单帧中间产物
  log/        run_YYYYmmdd_HHMMSS.log（明码文本，含参数/耗时/告警）
  report/     quality.pdf（LiMapper 同构）、quality.json、seamlines.geojson
```
