# 推扫拼图：架次工作台与安装配置

日期：2026-11-21  
分支：`feature/pushbroom-mosaic`  
范围：推扫拼图的前端交互、安装配置的数据模型与接口、相机标定改为后台运行，以及走查时发现的 bug。不改拼图算法，不改 worker 的投影和配准。

## 1. 结论

- 「新建推扫」和「推扫记录」合成一页「推扫拼图」，以架次为中心：左边选架次，右边提交、看进度、看结果、下载。
- 「相机标定」改成「安装配置」，只有管理员能看到。系统里可以保存多组安装配置，每组写明从哪天起生效。
- 新建任务时，后端按架次的飞行日期自动选一组配置，把名称和参数抄进任务。管理员可以给单个架次手动指定，覆盖自动选择。
- 相机标定改成后台运行：页面不再挂着一个长请求，离开页面结果也不会丢。
- 已提交、正在跑和已完成的任务不受配置修改影响。重跑沿用原任务的参数。这条规则不变。
- 配置里的两个参数值只能来自标定结果，不能手填。这条规则不变。

## 2. 走查发现的问题

| 位置 | 问题 | 原因 | 本次处理 |
| --- | --- | --- | --- |
| 推扫记录 | 鼠标停在某一行上，右侧固定的「操作」列变半透明，「提交时间」压在「详情」「删除」下面 | 主题里行悬停底色 `rowHoverBg` 是半透明的；框幅记录表用 `.jobs-table` 修过，推扫表没有套 | 工作台不再用宽表格，问题随之消失 |
| 相机标定 | 「来源」时间显示 UTC，比北京时间少 8 小时 | 前端直接截取 ISO 字符串 | 统一用 `formatJobDateTime` |
| 任务详情 | 运行日志的时间是 UTC，列表是北京时间 | `format_logs` 用 `astimezone(timezone.utc)` | 后端改成北京时间（UTC+8） |
| 相机标定 | 选 5 个以上架次时报网关超时，后端还在算 | 后端最多等 615 秒，nginx `proxy_read_timeout` 600 秒；标定是一个同步请求 | 改成后台运行，见第 5 节 |
| 新建推扫 | 填过任务名再换架次，名字还留着 | 表单不随架次重置 | 换架次时重置提交表单 |
| 新建推扫 | 0414 与 0419/0429 的安装不同，提交时不提示，跑完才在详情里警告 | 标定只有一组全局值 | 多组安装配置，按飞行日期自动选，见第 3 节 |
| 侧栏 | 直接打开推扫页面时，推扫菜单要等后端开关返回才出现，会闪一下 | 菜单依赖 `features` 加载 | 加载完成前，推扫菜单不参与展开状态的计算；加载完成后按当前地址展开 |

## 3. 安装配置

### 3.1 数据

新表 `pushbroom_mount_profiles`：

| 字段 | 说明 |
| --- | --- |
| `id` | UUID |
| `name` | 名称，例如「0414 安装」。不能为空，不能重名 |
| `effective_from` | 生效日期（北京时间的日期）。不能重复 |
| `along_offset_m`、`along_se_m` | 沿航向偏移及不确定度，米，两位小数 |
| `boresight_px`、`boresight_se_px` | 狭缝中心偏置及不确定度，像元，一位小数 |
| `flights` | 标定用的架次名列表 |
| `created_by`、`created_at` | 保存人和时间 |
| `updated_at` | 最后修改名称或生效日期的时间 |

新表 `pushbroom_flight_profiles`：架次名（目录名）到配置 `id` 的手动指定，一个架次最多一条。配置被删除时，指向它的手动指定一并删除。

两张表由 `bootstrap.py` 按现有方式建表。

### 3.2 迁移

启动时，如果 `pushbroom_mount_profiles` 为空、`pushbroom_calibrations` 有记录，取最新一条转成一组配置：

- 名称：`{标定架次里最早飞行日期的 MMDD} 安装`。现有数据会得到「0414 安装」。
- 生效日期：标定架次里最早的飞行日期。读不到飞行日期时，用该条标定的保存日期。
- 参数、不确定度、架次、保存人和保存时间照抄。

旧表保留，不再写入。迁移只做一次，配置表不为空就跳过。

### 3.3 飞行日期

`quick_check` 读 GPS 时，已经取到第一条和最后一条记录的 `UnixTime`。把第一条记录的时间作为 `flight.started_at`（ISO，带时区），一起返回。飞行日期取它对应的北京时间日期。

读不到 GPS 的架次本来就不能提交，不需要飞行日期。

### 3.4 选配置的规则

给一个架次选配置，按下面的顺序：

1. 有手动指定，用手动指定的那组。来源记为「手动」。
2. 在生效日期不晚于飞行日期的配置里，取生效日期最近的一组。来源记为「按日期」。
3. 都没有，用内置值（沿航向 1.70 m，狭缝中心 −19 像元）。来源记为「内置」。

规则只在后端实现，前端只展示后端给出的结果。

### 3.5 写进任务

新建任务时，后端按 3.4 选配置，把下面几项写进 `params`：

- `along_offset_m`、`boresight_px`：来源为「内置」时不写，worker 用自己的内置值。
- `mount_profile`：`{"id", "name", "source"}`。来源为「内置」时为 `{"source": "builtin"}`。

前端不能传这些字段，后端收到就返回 400。这和现在的规则一样。

## 4. 页面

### 4.1 菜单

「推扫拼图」分组下只留两项：

| 键 | 标签 | 路径 | 角色 |
| --- | --- | --- | --- |
| `pushbroom_workbench` | 推扫拼图 | `/pushbroom` | admin、executor |
| `pushbroom_mounts` | 安装配置 | `/pushbroom/mounts` | admin |

旧路径跳转：`/pushbroom/new`、`/pushbroom/jobs` 跳到 `/pushbroom`；`/pushbroom/jobs?job=<id>` 跳到 `/pushbroom?job=<id>`，工作台按任务找到对应的架次并选中；`/pushbroom/calibration` 跳到 `/pushbroom/mounts`。

已保存的角色菜单里如果有旧键：`pushbroom_new` 或 `pushbroom_jobs` 换成 `pushbroom_workbench`，`pushbroom_calibration` 换成 `pushbroom_mounts`。

### 4.2 工作台：左栏架次列表

- 顶上：搜索框（按架次名过滤）、刷新按钮、筛选：全部、运行中、未跑过、不可用，各带数量。
- 每个架次一张卡片：
  - 架次名；
  - 飞行日期和时间（北京时间）、数据大小；
  - 对应的配置：按日期或手动的，显示配置名；手动的额外标「手动」；内置的用橙色标「内置（没有对应配置）」；
  - 跑过几次、最近一次任务的状态；
  - 最近一次成功任务的缩略图，没有就留空；
  - 有任务在跑时，显示进度百分比。
- 能用的架次按飞行时间倒序排列，不能用的放在最后，卡片变灰，写出第一条错误原因，不能选中。
- 列表底部保留「列表里没有？填写目录」，核对通过后加入列表并选中；核对不通过时在输入框下面列出原因，不选中。
- 有任务在排队或运行时，每 3 秒刷新一次列表。

### 4.3 工作台：右侧所选架次

没有选中时，右侧提示「在左边选一个架次」。

**顶部**

- 架次名；飞行时间、飞行时长、行列波段、数据大小。
- 安装配置：名称和两个参数值。管理员看到「改选」，打开一个小窗：选一组配置，或选「按日期自动」撤销手动指定。
- 右侧「提交拼图」主按钮；旁边的「选项」下拉里有任务名称、分辨率、输出波段，默认任务名为空（用架次名）、自动分辨率、全部波段。换架次时这些选项重置。
- 不能用的架次不会被选中，所以顶部不出现「不能提交」的状态。

提交成功后，不跳转页面，历次任务列表最上面出现新任务并选中，中间区域显示排队状态。

**中间**

左侧是所选任务的主区域，右侧是这个架次的历次任务。

历次任务：

- 按提交时间倒序。每条显示编号、状态、提交时间、耗时、所用配置名。
- 默认选中最近一次。点一条，左侧主区域换成那一次。
- 每条有「…」菜单：重跑（失败或已取消时）、取消（排队或运行时）、删除（已结束时，可勾选同时删除成果目录）。

主区域按所选任务的状态显示：

| 状态 | 显示 |
| --- | --- |
| 排队中 | 「前面还有 N 个任务」，取消按钮 |
| 运行中、取消中 | 七步进度，当前一步显示百分比，取消按钮（取消中不显示） |
| 已完成 | 结果预览大图，可以滚轮缩放、拖动、全屏；标题行有「打包下载」「全屏查看」 |
| 失败 | 失败原因，「重跑」按钮 |
| 已取消 | 「已取消」，「重跑」按钮 |
| 没有任何任务 | 「这个架次还没跑过」，指向顶部的「提交拼图」 |

任务报告里有标定不符的提示时，在主区域上方显示黄色提示。管理员可以从这里跳到「安装配置」，并带上这个架次。

**底部页签**

| 页签 | 内容 |
| --- | --- |
| 成果文件 | 文件列表，可以逐个下载；标题旁的问号保留现在的文件说明 |
| 处理参数 | 架次目录、成果目录（可复制）、分辨率、输出波段、所用安装配置及两个参数值、提交人、第几次运行 |
| 各步耗时 | 七步各自的耗时 |
| 运行日志 | 日志全文，北京时间，运行中自动滚到最新 |

### 4.4 地址栏

`/pushbroom?flight=<目录名>&job=<任务 id>`。刷新或把链接发给别人，都回到同一个架次和同一次任务。只有 `job` 时，按任务的架次补上 `flight`。

### 4.5 安装配置页

只有管理员能看到。页面上有三块。

**配置表**

列：名称、生效日期、沿航向偏移、狭缝中心偏置、标定架次、保存人和时间、当前对到的架次数。

- 「改名称和日期」：只能改名称和生效日期，两个参数值不能改。
- 「删除」：确认框写明「已提交的任务不受影响；之后这些架次会按日期改用别的配置」。

**架次对应表**

列出所有能用的架次：飞行日期、对应的配置、来源（按日期、手动、内置）。手动的可以撤销。改了配置的生效日期以后，这张表立即反映新的对应关系。

**新建配置**

1. 勾选架次。计算服务不在线时，「开始标定」不可用，旁边写原因。
2. 点「开始标定」，见第 5 节。
3. 结果可用时，显示合并值、不确定度和每个架次的建议值，下面是名称和生效日期两个输入框。生效日期默认取所选架次里最早那天的飞行日期，名称默认「MMDD 安装」。
4. 点「保存为安装配置」。结果不可用时只显示原因和每个架次的情况，没有保存按钮。

标定提示文案保留：拆装前后的架次不要放在一起。

## 5. 标定改为后台运行

新表 `pushbroom_calibration_runs`：`id`、`status`（`running`、`done`、`failed`）、`input_dirs`、`result`（JSONB）、`error`、`created_by`、`created_at`、`finished_at`。

- `POST /api/pushbroom/calibration/runs`：核对架次，建一条 `running` 记录，起一个后台线程走现有的 RPC，然后立刻返回这条记录。线程拿到回复后写入 `result` 和 `done`；超时或出错写 `failed` 和原因。
- `GET /api/pushbroom/calibration/runs/{id}`：返回状态和结果。结果可用时附上 `run_token`，有效期 30 分钟，和现在一样。
- `GET /api/pushbroom/calibration/runs`：最近 10 次，安装配置页用来显示历史和恢复进行中的标定。
- 后端重启时，把仍是 `running` 的记录改成 `failed`，原因写「服务重启，标定中断」。
- 同一时间只允许一次标定在跑。已有一次在跑时再提交，返回 409。

页面每 3 秒查一次状态。离开再回来，进行中的标定和最近的结果都还在。

原来的 `POST /api/pushbroom/calibration/run` 和 `POST /api/pushbroom/calibration` 删除，换成上面的接口和第 6 节的配置接口。

## 6. 其他接口

| 接口 | 说明 |
| --- | --- |
| `GET /api/pushbroom/flights` | 每个架次加上：`started_at`、`mount`（`{id, name, source, along_offset_m, boresight_px}`）、`job_count`、`latest_job`（`{id, seq, status, global_percent, current_stage, has_preview, finished_at}`）。数量和最近任务一次查询取出，不按架次逐个查。非管理员只统计自己的任务 |
| `GET /api/pushbroom/jobs?input_dir=` | 按架次目录过滤，用于历次任务 |
| 任务返回体 | 加上 `queue_position`：排队中时，前面还有几个排队或运行中的任务；其它状态为空。`params.mount_profile` 照常返回 |
| `GET /api/pushbroom/mounts` | 配置列表，带每组当前对到的架次数 |
| `PATCH /api/pushbroom/mounts/{id}` | 只能改 `name`、`effective_from` |
| `DELETE /api/pushbroom/mounts/{id}` | 删除配置，连带删除指向它的手动指定 |
| `POST /api/pushbroom/mounts` | 用标定结果建配置：`run_id`、`run_token`、`name`、`effective_from`。参数值从这次标定的结果取，不收前端传来的数字 |
| `PUT /api/pushbroom/flights/{name}/mount` | 手动指定：`{"profile_id": ...}`；传 `null` 表示撤销 |

配置接口和手动指定只允许管理员调用，其它角色返回 403。所有修改写操作审计。

## 7. 出错时

| 情况 | 处理 |
| --- | --- |
| 计算服务不在线 | 工作台顶部黄色提示，可以提交，任务排队；安装配置页不能开始标定 |
| 架次文件损坏 | 左栏卡片写原因，不能选中 |
| 提交前配置被删除或改了日期 | 后端提交时重新按规则选，以提交那一刻的结果为准 |
| 标定超时或失败 | 记录为失败，页面显示原因，可以重新开始 |
| 标定结果超过 30 分钟才保存 | 返回 400「标定结果已失效，请重新标定」 |
| 配置名称或生效日期重复 | 返回 400，写明和哪一组重复 |

## 8. 测试

后端测试：

- 选配置：按日期取最近一组；生效日期当天算生效；手动指定优先；比所有配置都早时用内置值；删除配置后手动指定一并消失。
- 新建任务把 `mount_profile` 和参数写进 `params`；前端传参数值返回 400。
- 旧标定迁移成一组配置，只迁移一次。
- 后台标定：`running` 到 `done`、到 `failed`，重启后 `running` 变 `failed`，同时只允许一次。
- 排队位置。
- 架次列表的 `job_count`、`latest_job`；非管理员只统计自己的任务。
- 日志时间是北京时间。
- 配置接口和手动指定的权限。

前端：打包通过，没有类型错误。

浏览器走查：选架次、提交、看排队和进度、看结果、全屏、打包下载；在安装配置页新建配置、改生效日期、手动指定、撤销，回到工作台看对应关系变化；旧地址跳转；刷新后停在同一架次和任务。
