# 拼图 Worker 保护方案（汇报）

日期：2026-11-16  
对象：领导汇报  
范围：交给客户的计算程序（worker），以及我方发版台

---

## 1. 结论

客户机器归客户管，目录权限挡不住拷贝。现在的做法不是把源码加密后再在客户机器上解密，而是两件事一起做：

1. **算法不交付明文。** 拼图核心模块在我方构建时编译成机器码（`.so`），客户镜像里删掉对应的 `.py`。
2. **没有有效许可就不能算。** 许可由我方私钥签名。私钥只留在发版台。客户镜像里只有验签用的公钥。新许可绑定机器，并定期向发版台领取最多 72 小时的租约。发版台停用后，客户一旦连上服务器就会停；断网时已领到的租约到期也会停。

页面和任务接口仍是普通程序。算法在 worker 里，保护做在 worker 上。

同一版镜像给多个客户用。每个客户单独签发许可，续期换许可文件，不用重新打包镜像。

---

## 2. 要防的是什么

以前线上算法是明文 Python，放在服务器的 `ms_mosaic` 目录。试用账号进不了这个目录，但程序一旦装到客户自己的服务器上，对方就是管理员，可以把目录整份拷走。

要收起来的是拼图算法，以及把算法讲清楚的内部文档。客户本来就要用的页面、接口说明可以留着。

---

## 3. 客户实际拿到什么

交付包里有：

- 页面、接口、worker、数据库、消息队列的离线镜像
- 一份该客户的许可文件（`.lic`）
- 操作手册
- 不含源码挂载的启动文件

交付包里没有：

- 发版台
- 签发私钥
- 已编译模块对应的算法 `.py`
- git 历史和内部设计文档

客户 worker 启动时强制验许可（开发环境默认不强制，避免影响我方日常开发）。构建结束时会检查核心模块 `pipeline.py` 不在镜像里。

当前编进机器码的是匹配、正射、融合、DSM、GPU 等算法模块，清单在 `release/build/cython_modules.txt`。启动入口和验签程序仍是 Python，否则程序无法在客户机器上做许可判断。

---

## 4. 许可怎么生效

许可文件是一份 JSON，外加 Ed25519 签名。客户改任何一个字段，签名都会失败。

校验顺序：

| 步骤 | 不通过时 |
| --- | --- |
| 签名正确，且产品名是 `spectrum-mosaic` | 拒绝启动 |
| 当前时间在生效日和到期日之间（按 UTC） | 提示尚未生效，或已过期 |
| 若许可写了机器指纹：必须等于这台机器 `/etc/machine-id` 的指纹 | 提示与当前机器不匹配 |
| 绑定机器的许可要向发版台领取租约 | 见下文 |
| 本机时间相对上次成功校验回拨超过容差（默认 1 小时） | 提示疑似时钟回拨 |

机器指纹在客户执行启动脚本时打印。换机器必须重新签发，不能把旧许可拷到另一台机器上继续用。

**租约。** 新签发的许可都带机器指纹。worker 启动时，以及之后每 6 小时，向发版台换一次租约。租约最长 72 小时，且不会超过许可到期日。

- 发版台明确拒绝（已停用、机器不对、未生效、已过期）：立刻退出，并清掉本机租约。
- 暂时连不上发版台：若本机还有未过期的租约，可以继续算；没有租约则不能启动。
- 没有机器指纹的旧许可：不联网，只做本地验签和到期判断。新接口已经要求必须填写机器指纹。

时钟记录写在客户数据目录 `data/.license/clock.json`。换一张新许可会重新计时。这是为了防止把系统时间改回去继续用过期许可。对方如果删掉这个文件，记录会重置，所以它提高的是随意改时间的成本，不是绝对封死。

## 5. 发版台管什么

发版台只装在我方，不进客户包。已经部署在 `39.103.56.168`，目录 `/home/spjiangl/mosaic_release`。页面端口 8180，外网安全组尚未放行。

发版台负责：

- 按版本、按 CPU 架构构建客户镜像（amd64 / arm64 可并存）
- 客户档案
- 签发、停用许可，填写生效日、到期日和机器指纹
- 打交付包（镜像、许可、操作手册、启动说明）
- 响应客户 worker 的租约请求

私钥在服务器的 `release/keys/`，不进 git，不进客户镜像。公钥在构建客户 worker 时打进镜像。

停用许可只影响发版台之后的租约。已经发出、且不带机器指纹的旧文件，离线侧仍看到期日，不能远程立刻作废。带机器指纹的许可，下一次联网换租约时就会被拒绝。

## 6. 能挡住什么，挡不住什么

**能挡住**

- 直接打开文件阅读、拷走就能运行的算法源码
- 客户自己改到期日、改客户名（没有私钥，签名对不上）
- 把许可拷到另一台已绑定的机器之外使用
- 发版台停用后，绑定许可在联网时立即失效；断网最多再用到当前租约结束（不超过 72 小时）
- 把系统时间往回拨来延长使用（在不删除时钟记录的前提下）

**挡不住，汇报时需要讲清楚**

- 程序必须在客户机器上运行。有逆向经验的人仍可以分析机器码，这不是“算法不可还原”。
- 客户有 root。验签入口仍是可读程序，决心改入口的人可以绕过许可。编译和许可提高的是直接盗用的成本，不是在对方完全控制的机器上做到不可破解。
- 页面和接口没有做同样的编译。算法不在这两侧。
- 不带机器指纹的旧许可无法在线吊销。

因此这套方案适合私有化交付：客户现场经常不能一直连外网，计算仍在客户本机完成，同时把“拷走源码”和“自己改许可”挡在普通使用之外。

---

## 7. 和最初设想的差别

最初写过一版“完全离线、不绑机器、停用只记账”。按客户现场会断网来看，离线验签仍然保留。当前实现在此之上增加了三件事，都已经写进客户操作手册：

- 生效日，未到日期不能算
- 机器绑定，以及 72 小时租约
- 时钟回拨检测

续期仍然是我方重新签发一份许可，客户替换文件后重启，不需要重新做镜像。
