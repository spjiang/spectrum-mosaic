# 推扫拼图：RTK / PPK 定位确认清单

给无人机与相机团队。目的：确认能否拿到厘米级定位，把推扫成果的航带间错位和绝对位置再往下压。

## 1. 现状

推扫拼图按 `figspec.gps` 的定位做直接地理编码，再用航带重叠做配准修正。几个架次修正后：

| 指标 | 数值 |
| --- | --- |
| 同一块区域内的错位（精配准后，中位） | 约 0.15 m |
| 航带之间的整体平移（配准测得，需要修正掉的量） | 0.2～0.9 m |
| 绝对位置 | 以机载定位为准，无法自检 |

从现有数据看到的情况：

- `figspec.gps` 每秒 1 条，列为 `Lines, UnixTime, Microseconds, Latitude, Longitude, Altitude, W, X, Y, Z, XVelocity, YVelocity, ZVelocity, UAVTimeMs, SysUnixTime, SysMicroseconds`，**没有定位状态（单点 / 差分 / 浮点 / 固定）和卫星数**。
- 轨迹很平滑：1 Hz 点相对平滑曲线的残差只有 2～4 cm。但飞控输出的融合位置本来就平滑，不能据此判断是 RTK。
- 航带之间要修正 0.2～0.9 m 的整体平移。若是 RTK 固定解，这个量应在几厘米。**因此推测这几次飞行用的是单点或融合定位**，请确认。

## 2. 请确认的问题

1. **RTK 设备**：飞机型号；是否装有 RTK 模块（网络 RTK 还是自架基站）；0414、0419、0429 这几次是否开启、是否为固定解。
2. **定位来源**：`Latitude / Longitude / Altitude` 是飞控融合输出，还是 GNSS 接收机直出？坐标系是 WGS84 还是 CGCS2000？高度是椭球高还是海拔高？
3. **能否加列**：能否在 `figspec.gps` 增加定位状态、卫星数、水平 / 垂直精度估计；记录频率能否提高到 5～10 Hz。
4. **PPK 可行性**：机上是否记录 GNSS 原始观测（RINEX 或厂家二进制）？有没有同时段基站数据？PPK 解算后能否导出逐历元轨迹（GPS 时间、经纬度、高度、解状态、标准差）？
5. **时间同步**：`UnixTime` 是 GNSS 时间还是相机系统时间？相机行触发是否与 GNSS 秒脉冲（PPS）同步？`UAVTimeMs` 与飞控日志如何对应？
6. **杆臂与姿态**：GNSS 天线相位中心到相机光心的偏移（前 / 右 / 下，厘米）；云台是否增稳；`W, X, Y, Z` 的含义与单位（四元数？角度×100？）。
7. **测试架次**：能否飞一个开启 RTK 固定解的架次，同一测区往返至少 3 条航带；若测区内有已知坐标的地面检查点，一并提供坐标。

## 3. 拿到数据后我们做什么

- 支持两种输入：`figspec.gps` 里直接带 RTK 字段；或另附 PPK 轨迹文件，按时间对齐替换机载定位。
- 按解状态加权：固定解段直接使用；浮点 / 单点段降权，仍靠航带配准修正。
- 用测试架次验收：航带间整体平移应降到 0.1 m 以内；有检查点时给出绝对误差统计，写进质量报告。

问题 1、2、5 决定方案，优先回复；其余可随测试架次一起提供。
