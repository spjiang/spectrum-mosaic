# 框幅拼图：Wayho RGB 相机（rgb1）接入说明

给项目与客户对接人员。记录 Wayho 相机数据怎样接进现有拼图、试跑结果，以及还要向客户确认的问题。

## 1. 数据是什么

样例目录 `mosaic/server/data/input/rgb1`（容器内 `/data/input/rgb1`）。

| 项 | 情况 |
| --- | --- |
| 文件 | `000000.tif`～`000044.tif`，共 45 张，1.5 GB |
| 影像 | 4024×3036，**三通道 8 位彩色**，未压缩。资源管理器显示的图标看不出通道数，实际不是单通道 |
| 相机 | 厂商 `Wayho`，型号 `VEN-1220-32U3C-FPC-M05`，镜头 12 mm |
| 拍摄 | 2026-11-08 12:45～12:48，深圳龙华一带 |
| 航线 | 4 条东西向航线，每条 9～10 张，另有 8 张在转弯处；航向重叠约 74%，旁向约 69% |
| 定位 | 每张都有经纬度、航向和相对起飞点高度（约 124 m） |
| 姿态 | 俯仰、横滚都写 0，实际是正下视 |
| 绝对高程 | **没有**（EXIF 高度是 0，XMP 也没写海拔） |

## 2. 怎样接进来

不需要新增拼图模式。Wayho 和 MAX 一样是框幅相机，空三、密集匹配、DSM、正射的算法完全相同，差别只在**读数据**这一步。因此在「框幅拼图」里加了一层「相机适配」：

| 差异 | MAX 多光谱相机 | Wayho VEN 系列 RGB 相机 |
| --- | --- | --- |
| 文件命名 | `MAX_<编号>_<Color/波长nm>_<D/W/R>` | `<编号>.tif` |
| 波段 | Color + 多光谱 | 只有 Color |
| 正下视的写法 | 俯仰 = −90 | 俯仰 = 0、横滚 = 0 |
| 焦距初值 | 按 MAX 标定比例 | 镜头焦距 ÷ 像元尺寸 |
| 高度 | 有绝对高程 | 只有相对起飞点高度 |

使用方式：

- 处理方案「影像编目」里新增 **相机类型**，默认「自动识别」：文件名是 `MAX_` 开头的按 MAX 读；序号命名且型号为 `VEN-*` 或厂商为 Wayho 的按 Wayho 读；都不是就在编目阶段报错并说明原因。也可以手动指定。
- 同一处新增 **像元尺寸（µm）**，留空时按型号表取值（`VEN-1220` 为 1.85 µm）。以后换新型号相机，在这里填厂家给的像元尺寸即可。
- 「新建处理」填完测区目录后会显示识别结果，例如「相机：Wayho VEN 系列 RGB 相机（自动识别），45 张 Color，无多光谱」。
- 命令行对应参数为 `--camera-source`（`auto` / `max_ms` / `wayho_rgb`）和 `--pixel-size-um`。

以后接其它相机，照同样方式加一个读法即可，菜单和拼图算法都不用动。

| 指标 | 结果 |

| 参与计算 | 45 / 45 张 |

## 4. 需要注意的三点

### 4.1 相机参数是推断的，请客户确认

拼图需要知道镜头焦距和传感器每个像素的大小，两者配合才能算准。

- 焦距：照片里写了 12 mm。
- 像素大小：照片里没写。按照片尺寸 4024×3036 推断传感器是 Sony IMX226，像素大小 1.85 微米。

拼图时程序会根据照片之间的重叠自行校正。校正结果相当于焦距约 13.4 mm，比标称的 12 mm 稍大。

- **影响**：拼出来的图不受影响，程序用的是校正后的值。
- **建议**：向客户确认像素大小和镜头实际焦距。拿到准确数值后，起算更准，换型号时也不会算偏。

### 4.2 只有相对高度，没有海拔

照片记录的高度是无人机比起飞点高了多少米，不是海拔。所以 DSM 里的数字表示「比起飞点高几米」，例如测区地面约为 19 m，意思是比起飞点高约 19 米。

- **影响**：正射图正常；DSM 只能看相对高低，不能当海拔用。
- **如需海拔**：客户提供带海拔的定位数据，或在地面布设控制点。

### 4.3 分辨率在空三之后才确定（已改）

飞机离地越近，拍得越细。照片里写的 124 米是离**起飞点**的高度；测区地面比起飞点高约 19 米，实际离地只有约 107 米。

网页「新建处理」在计算开始前就要定分辨率，原来只能按 124 米估算，锁定为 1.92 cm，比实际能做到的 1.49 cm 粗约 30%。

现在的做法（2026-11-21 定）：

- **Wayho 这类只有相对高度的相机**：提交时只记下「降低分辨率」的倍数，不锁定具体数值。空三完成后，程序按实际离地高度和校正后的焦距算出分辨率，再乘以倍数。页面上显示的是预估值，例如「不降低 约 0.0192 m」，并提示空三后确定。任务详情里两项分辨率在运行中显示「空三后确定」，完成后自动填入实际值。
- **MAX 相机**：不变，仍在提交时锁定分辨率。

网页提交 rgb1 验证（倍数 1，约 10 分钟）：正射 1.489 cm（15490×11734），DSM 2.98 cm，任务记录自动回填 0.01489 m。

- **代价**：同一批 Wayho 数据重跑时，空三校正结果可能有细微差别，分辨率会差一点点，两次成果的像素格子不一定完全对齐。像素比原来多约 1.7 倍，正射文件更大、耗时略长。
- **需要固定分辨率时**：在处理方案里手动填写「DSM 分辨率」（正射为其一半），程序就按填写的值出图，不再随空三变化。

## 5. 请客户确认的问题

1. 相机 `VEN-1220-32U3C-FPC-M05` 的传感器型号与像元尺寸（是否为 IMX226、1.85 µm）。
2. 镜头实际焦距（标称 12 mm，校正结果约 13.4 mm）；是否有出厂标定参数（焦距、主点、畸变）。
3. 能否在照片里写入海拔（椭球高或海拔高，并说明坐标系）；或提供同时段的定位文件。
4. 是否有 RTK；`GPSXYAccuracy = 3 m` 是否就是实际定位精度。
5. 曝光偏暗是否为有意设置；成果需要整体提亮时，是否以某张参考片的色调为准。

问题 1、2 影响计算起点，3 决定 DSM 能否给海拔，请优先回复。

## 6. 部署

客户机需要重新构建并部署后端、worker、前端三个镜像。新参数的数据库迁移 `030_camera_source.sql` 在后端启动时自动执行，已有处理方案不用改，默认就是自动识别。
