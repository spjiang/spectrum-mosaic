# 拼图服务私有部署操作手册

本文说明高光谱拼图服务在 Windows 与 Linux 上的安装、启动和数据目录。网页中的任务提交与成果验收见《拼图服务WEB操作手册》。

发版台仅在供应商侧使用，不包含在交付包中。

## 1. 交付包

解压后的目录如下。`data/` 在首次启动后出现。`images/` 仅离线全量包包含。

```text
├── start.cmd                 Windows 双击启动
├── start.ps1                 Windows 启动脚本
├── start.sh                  Linux 启动脚本
├── uninstall.cmd             Windows 卸载，不删用户数据
├── uninstall.ps1
├── uninstall.sh              Linux 卸载，不删用户数据
├── docker-compose.yml
├── docker-compose.gpu.yml    NVIDIA 覆盖层；由启动脚本按需叠加
├── .env.example
├── README.md
├── licenses/<许可ID>.lic
├── docs/
│   ├── 拼图服务私有部署操作手册.md
│   └── 拼图服务WEB操作手册.md
├── data/                     航片、成果、许可时钟
├── pgdata/                   首次启动后出现，数据库文件，不要删除
└── images/
    ├── worker-image.tar
    ├── pushbroom-worker-image.tar   推扫计算服务，版本含推扫时才有
    ├── backend-image.tar
    ├── frontend-image.tar
    ├── postgres-image.tar
    └── rabbitmq-image.tar
```

镜像架构写在文件名中，为 `amd64` 或 `arm64`。64 位 Windows 与 Linux（Intel / AMD）使用 `amd64`。架构不一致时容器无法启动。

下文以交付包位于 `E:\spectrum-mosaic`（Windows）和 `/opt/spectrum-mosaic`（Linux）为例。实际路径不同时，只替换该根目录。

## 2. Windows

### 2.1 安装前

1. 安装 Docker Desktop。引擎选择 WSL 2，不要启用 Windows 容器。确认左下角为 Engine running。
2. 开启 Windows 自动对时。许可按 UTC 判断生效与到期。
3. 确认 `licenses\` 中有 `.lic`，且当前日期在生效日与到期日之间。
4. 交付包已含镜像，不要再编译，也不要把拼图源码挂进容器。

核对压缩包 SHA-256，与供应商给出的值一致后再解压。在交付包所在目录执行：

```powershell
Get-FileHash .\交付包.zip -Algorithm SHA256
```

### 2.2 启动与停止

在 `E:\spectrum-mosaic` 执行，不要进入其中的嵌套文件夹。双击 `start.cmd`，或执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

脚本会创建 `data\`，在没有 `.env` 时由 `.env.example` 生成。本机还没有镜像时才导入 `images\`；镜像已经在时跳过导入，然后启动。本机有 NVIDIA 且 `nvidia-smi` 可用时，自动把显卡交给 worker，新建处理的「任务 GPU」会列出卡名。没有显卡、或 Docker 传不进 GPU 时走 CPU，结果相同，耗时增加。有显卡时请用 `start.cmd`，不要只执行 `docker compose up -d`。第一次导入时窗口会停留，等待结束，不要关闭。

本机页面为 `http://localhost:9080/`。端口以 `.env` 中的 `FRONTEND_PORT` 为准。其他电脑访问时，将 `localhost` 换成这台机器的 IP，并放行该端口。

查看状态与日志：

```bat
cd /d E:\spectrum-mosaic
docker compose ps
docker compose logs --tail=50 worker
```

停止：

```bat
docker compose down
```

关机或重启后，仍双击 `start.cmd`。镜像已在本机时不会再次导入。

### 2.3 数据目录

页面路径以 `/data` 开头。`E:\spectrum-mosaic\data` 即容器内的 `/data`。生产作业使用 `admin`。测区名为 `测区数据1` 时：

| 页面填写 | Windows 目录 |
| --- | --- |
| `/data/input/测区数据1` | `E:\spectrum-mosaic\data\input\测区数据1` |
| `/data/output/runs/测区数据1` | `E:\spectrum-mosaic\data\output\runs\测区数据1` |

航片按原架次整夹拷入输入目录。支持 JPG、TIFF。成果在输出目录下的时间戳文件夹内，子目录名为 `拼图结果`。网页操作见《拼图服务WEB操作手册》。

账号、任务和处理记录在交付包根目录的 `E:\spectrum-mosaic\pgdata`。不要删除这个目录，也不要把它挪进 `data`。`docker compose down` 不会清掉它。

### 2.4 卸载

双击 `uninstall.cmd`。脚本只删除本交付包的容器和镜像，不使用会清数据卷的参数。

保留 `data\`、`pgdata\`、`licenses\` 和 `.env`。航片、成果、账号和任务都还在。再次双击 `start.cmd` 会重新导入镜像并沿用这些数据。

## 3. Linux

### 3.1 安装前

1. 安装 Docker Engine 与 Docker Compose 插件，并确认服务已启动。
2. 启用 NTP，保证系统时间准确。许可按 UTC 判断生效与到期。
3. 确认 `licenses/` 中有 `.lic`，且当前日期在生效日与到期日之间。
4. 执行 `uname -m`。`x86_64` 对应交付包 `amd64`，`aarch64` 对应 `arm64`。
5. 交付包已含镜像，不要再编译，也不要把拼图源码挂进容器。

核对压缩包：

```bash
sha256sum 交付包.zip
```

### 3.2 启动与停止

在 `/opt/spectrum-mosaic` 执行：

```bash
chmod +x start.sh
./start.sh
```

脚本会创建 `data/`，在没有 `.env` 时由 `.env.example` 生成。本机还没有镜像时才导入 `images/`；镜像已经在时跳过导入，然后启动。有 NVIDIA 时自动启用 GPU；没有卡则走 CPU。第一次导入时终端会停留，等待结束。

本机页面为 `http://localhost:9080/`。端口以 `.env` 中的 `FRONTEND_PORT` 为准。其他机器访问时，将 `localhost` 换成服务器地址，并放行该端口。

查看状态与日志：

```bash
docker compose ps
docker compose logs --tail=50 worker
```

停止：

```bash
docker compose down
```

关机或重启后，仍执行 `./start.sh`。镜像已在本机时不会再次导入。

### 3.3 数据目录

页面路径以 `/data` 开头。`/opt/spectrum-mosaic/data` 即容器内的 `/data`。生产作业使用 `admin`。测区名为 `测区数据1` 时：

| 页面填写 | Linux 目录 |
| --- | --- |
| `/data/input/测区数据1` | `/opt/spectrum-mosaic/data/input/测区数据1` |
| `/data/output/runs/测区数据1` | `/opt/spectrum-mosaic/data/output/runs/测区数据1` |

航片按原架次整夹拷入输入目录。支持 JPG、TIFF。成果在输出目录下的时间戳文件夹内，子目录名为 `拼图结果`。

账号、任务和处理记录在交付包根目录的 `/opt/spectrum-mosaic/pgdata`。不要删除这个目录，也不要把它挪进 `data`。`docker compose down` 不会清掉它。

### 3.4 卸载

在交付包根目录执行 `./uninstall.sh`。脚本只删除本交付包的容器和镜像。`data/`、`pgdata/`、`licenses/` 和 `.env` 保留。再次执行 `./start.sh` 会重新导入镜像并沿用这些数据。

## 4. 账号

两个系统使用同一套账号。首次登录后修改 `admin` 密码。

| 账号 | 初始密码 | 权限 | 数据目录 |
| --- | --- | --- | --- |
| `admin` | `admin123` | 管理员，可使用全部菜单 | `/data/input/<测区名>`、`/data/output/runs/<测区名>` |
| `trial1` | `trial@123456` | 受限作业账号，约 30 天有效 | `/data/input/trial1/<测区名>`、`/data/output/runs/trial1/<测区名>` |
| `trial2` | `trial@123456` | 与 `trial1` 相同，目录名为 `trial2` | `/data/input/trial2/<测区名>`、`/data/output/runs/trial2/<测区名>` |

`trial1` 与 `trial2` 不能访问对方目录，也不可见系统配置、用户管理和计算节点。到期后联系供应商，不要直接修改数据库。

## 5. 许可

worker 启动时校验 `licenses/` 中的 `.lic`。签名无效、尚未生效、已经过期，或系统时间相对上次成功校验回拨过大时，worker 退出。日志为「许可无效或已过期」「许可尚未生效」或「系统时间异常，疑似时钟回拨」。

未绑定机器的许可只在本机验签。已绑定机器的许可必须与本机指纹一致。交付包已把 `LICENSE_SERVER_URL` 写入 `.env.example`（只写根地址，不要带路径），首次启动会复制到 `.env`。启动脚本会打印本机指纹。更换机器须由供应商重新签发并替换 `.lic`。

续期：

1. 向供应商索取新的 `.lic`。
2. 替换 `licenses/` 中的旧文件。不要手工修改文件内容。
3. 执行 `docker compose up -d --force-recreate worker`。开启了推扫时改为 `docker compose up -d --force-recreate worker pushbroom-worker`。
4. 打开页面，确认可以登录并提交任务。

不要删除 `data/.license/` 下的 `clock.json`、`pushbroom-clock.json`。

推扫计算服务与 worker 使用同一份 `.lic`，许可无效时同样退出，日志用 `docker compose logs --tail=50 pushbroom-worker` 查看。

## 6. 推扫拼图

推扫拼图处理 FigSpec 推扫高光谱相机的架次，由单独的推扫计算服务 `pushbroom-worker` 执行。网页操作见《拼图服务WEB操作手册》第 14 节。

### 6.1 开启与关闭

版本含推扫时，`.env.example` 中已默认开启：

```text
PUSHBROOM_ENABLED=true
COMPOSE_PROFILES=pushbroom
```

关闭时把两行改成 `PUSHBROOM_ENABLED=false`、`COMPOSE_PROFILES=`，重新执行启动脚本：推扫菜单隐藏，推扫计算服务停止并删除容器，已有成果不受影响。再开启时改回两行，重新执行启动脚本。

从旧版本升级时，原来的 `.env` 会保留，里面没有这两行，推扫默认不开。启动脚本会提示；需要时把 `.env.example` 中的两行抄进 `.env`，重新执行启动脚本。

推扫计算服务默认最多使用 12 GB 内存（`PB_MEM_LIMIT=12g`），算法自身预算 8 GB（`PB_MAX_MEMORY_GB=8`）。内存小的机器两者同比调低，预算要比上限小几 GB。

### 6.2 数据目录

架次整夹放在 `data/input/pushbroom/` 下，一个子目录一个架次，内含 `figspec.hdr`、`figspec.spe`、`figspec.gps`。成果在 `data/output/pushbroom/<架次>/<时间戳>/`。

| 页面路径 | Windows 目录 | Linux 目录 |
| --- | --- | --- |
| `/data/input/pushbroom/<架次>` | `E:\spectrum-mosaic\data\input\pushbroom\<架次>` | `/opt/spectrum-mosaic/data/input/pushbroom/<架次>` |
| `/data/output/pushbroom/<架次>` | `E:\spectrum-mosaic\data\output\pushbroom\<架次>` | `/opt/spectrum-mosaic/data/output/pushbroom/<架次>` |

一个全波段架次原始数据约 30～50 GB，成果与原始数据量相当，按此预留磁盘。

### 6.3 推扫相机标定

推扫成果的几何精度依赖相机在飞机上的安装参数。内置参数按出厂 FS-60C 安装标定，相机未拆装时不用改。**拆装或更换相机后**须重新标定，否则航带之间会错开约 1 米，质量报告「传感器标定自检」会出现加粗警告。

1. 用重装后飞的架次标定。架次要有往返航带（至少 3 条去程、3 条回程，常规作业航线即可）；有两个以上架次时一起标定更稳。
2. 在交付包根目录执行（架次名换成实际名称，`--input` 可写多个）：

   ```bash
   docker compose run --rm --no-deps pushbroom-worker python -m pb_mosaic calibrate --input /data/input/pushbroom/FigSpec_260419_132008 --input /data/input/pushbroom/FigSpec_260429_134344
   ```

   每个架次不超过 1 分钟。成功时输出末尾为两行建议值，例如：

   ```text
    "env": [
     "PB_SENSOR_ALONG_OFFSET_M=1.64",
     "PB_SENSOR_BORESIGHT_PX=-19.3"
    ]
   ```

   输出里 `"usable": false` 时不要填写：常见原因是往返航带不够，或所给架次分属拆装前后两种安装状态。换架次重试，或把输出发给供应商。
3. 把两行（去掉引号）写进 `.env`，执行 `docker compose up -d pushbroom-worker` 使其生效。之后提交的任务使用新参数；已完成的任务需重新提交。
4. 新任务的质量报告「传感器标定自检」不再出现警告，即标定完成。

不要按经验手改这两个值。

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| 页面打不开 | 确认 Docker 引擎在运行，执行 `docker compose ps`，按 `FRONTEND_PORT` 访问 |
| `exec format error` 或容器立即退出 | 交付包架构与本机不一致，或镜像导入时磁盘写坏。更换对应架构的包，或按供应商说明重新导入 |
| worker 反复退出 | 执行 `docker compose logs --tail=50 worker`，按第 5 节核对许可、时间与 `.env` |
| 「任务 GPU」没有本机显卡 | 确认用 `start.cmd` / `start.sh` 启动，窗口有「启用 GPU」。Windows 须为 Docker Desktop + WSL 2，且 `nvidia-smi` 能列出 NVIDIA 卡。当前包若是 CPU 版 worker，须换 GPU 版 amd64 镜像 |
| 提交提示路径不在允许范围内 | `admin` 使用 `/data/input` 与 `/data/output/runs`。`trial1`、`trial2` 必须带自己的用户名目录 |
| 不能同时提交第二条任务 | 已有任务排队或运行时，等待其结束 |
| 看不到「推扫拼图」菜单 | 按第 6.1 节核对 `.env` 的 `PUSHBROOM_ENABLED`、`COMPOSE_PROFILES`，改后重新执行启动脚本 |
| 推扫任务一直「等待计算服务」 | 执行 `docker compose ps pushbroom-worker`。没在运行时查看 `docker compose logs --tail=50 pushbroom-worker`，按第 5 节核对许可 |
| 推扫任务失败，提示「计算进程被系统强制结束」 | 多半是内存不足。按第 6.1 节调小 `PB_MAX_MEMORY_GB`；机器内存充裕时也可调大 `PB_MEM_LIMIT` |
| 推扫成果航带之间明显错开 | 查看质量报告「传感器标定自检」，有警告时按第 6.3 节重新标定 |
